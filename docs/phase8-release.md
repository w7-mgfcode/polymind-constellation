## Delivered boundary

Phase 8 makes the three canonical skills consumable by downstream repositories
without turning Polymind into a provider marketplace or executable local-agent
runtime. The wheel and source distribution carry the synchronized generated
projection. `polymind install` copies only Polymind-owned per-skill directories
into `.agents/skills/` and `.claude/skills/`, plus its bounded state under
`.polymind/`.

The installer defaults to a non-mutating plan and supports bounded diff,
explicit apply, drift check, stale-lock diagnosis, and one-generation rollback.
It rejects source drift, path traversal, symlinks, unmanaged conflicts, and
modified managed files. Interrupted apply and rollback paths restore the state
that existed before the command.

## Honest release scope

This pre-1.0 release does not satisfy the architecture-wide production
definition of done. Claude live invocation, OpenCode discovery through a local
model, and cross-provider trigger/approval parity remain open. The Ollama
measurements are data-only routing evidence and explicitly failed the required
strict approval-stop threshold. No provider-native plugin, extension,
marketplace, hosted registry, or executable generic local harness is included.

See the [Phase 7 conformance record](phase7-conformance.md),
[provider compatibility matrix](provider-compatibility.md), and
[versioning policy](versioning.md) for the evidence boundary and release rules.
